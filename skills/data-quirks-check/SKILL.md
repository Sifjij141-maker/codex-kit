# 데이터 함정 점검표

각 항목을 실제 데이터로 확인하고 "발견 | 근거(파일·행·예시) | 영향 | 확인이 필요한 점" 표로 보고한다.
고치지 말고 보고만 한다. 개인정보 값은 가린 채 예시를 든다.

1. 인코딩: UTF-8로 안 읽히는 파일(CP949 등), BOM, 깨진 한글. `errors="ignore"`처럼 오류를 숨기는 코드.
2. ID 형식: 앞자리 0 누락, 접두어(C-, M 등), 자릿수 차이, 숫자가 아닌 ID(테스트·시스템·협력사 계정).
3. 같은 종류 파일 여러 개: 날짜가 붙은 스냅샷이 누적인지 증분인지, 둘 다 읽으면 중복되는지, 최신 파일을 고르는 기준.
4. 중복: 완전히 같은 행, 같은 키에 다른 값, 같은 대상이 여러 번 기록된 경우.
5. 시간: 시간대(끝에 Z면 UTC), 기간 경계(첫날 0시, 마지막 날 24시), '오전/오후 12시' 표기, 날짜 형식 혼재.
6. 기준 시점: 기준일보다 뒤의 기록(예정된 변경), 기준일 당시 상태를 다시 계산해야 하는 변경 이력.
7. 판단 보류: 기간 끝부분이라 아직 결과를 알 수 없는 레코드(며칠 안의 재발생, 기한 전 미처리).
8. 매칭: 키가 비었거나 틀린 행, 이름으로 찾을 때 동명이인, 소속·표기 차이(공백, 접미어), 대소문자.
9. 분류 코드: 기간 중 코드 개편, 옛 코드와 새 코드 대응, 시스템마다 다른 분류 이름.
10. 문서와 데이터의 불일치: 규칙 문서에 없는 열, 문서 기준과 맞지 않는 값 분포.
11. 이력 파일: 시간순 정렬 여부, 같은 대상의 상태가 여러 번 바뀐 경우, 최신 상태를 정하는 기준.
12. 개인정보: 연락처, 생년월일, 이메일, 주소, 주민·계좌·카드번호 같은 열과 자유 텍스트 안의 개인정보. 화면·파일로 나가면 안 되는 것.
13. 출력 제약: 받는 시스템의 파일 형식, 인코딩, 자릿수, 코드값.

마지막에 규칙을 정하기 전에 사람이 확인해야 할 점을 영향이 큰 순서로 5개 정리한다. 규칙을 직접 정하지는 않는다.
