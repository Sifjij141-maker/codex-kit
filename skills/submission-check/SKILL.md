# 제출 전 점검

고치지 말고 먼저 점검해 "항목 | 상태 | 근거 | 조치 필요" 표로 보고한다. 사용자가 승인한 것만 고친다.

1. 실행 조건: README의 실행 명령, 주소, 포트대로 서버가 뜨는지. 필요한 패키지가 requirements 파일에 있는지.
2. 테스트: 전체 테스트를 실행하고 통과·실패 수를 그대로 보여 준다.
3. 제출 문서: README가 요구한 문서가 모두 있는지. 정의표, 결정과 근거, 검증 숫자, 남은 한계가 들어 있는지.
4. 문서와 코드의 일치: 문서에 적힌 숫자와 규칙이 지금 코드의 결과와 같은지. 실행 방법 문서의 명령이 실제로 동작하는지.
5. 개인정보: 화면, API 응답, 내보내는 파일에 나가면 안 되는 정보가 없는지.
6. 출력 파일: 형식, 인코딩, 행 수, 키 자릿수가 요구와 같은지.
7. git: 커밋되지 않은 변경, 마지막 커밋 메시지에 무엇을·왜가 있는지.

마지막에 확인 질문 대비 요약을 한 화면 분량으로 만든다:
구조(파일별 역할), 핵심 함수 5개, 결정 5개와 근거, 검증 숫자, 남은 한계 3개.
